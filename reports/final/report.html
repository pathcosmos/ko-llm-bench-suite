요약

사용자 모델 3종을 같은 엔진·정밀도·프롬프트로 공개 모델과 비교했다. 객관식·PPL은 로그우도, 생성은 규칙 채점 + judge(Qwen3.6-35B-A3B) + 코드 격리 실행, 다턴 시나리오는 자체 규칙 채점, 속도는 클라이언트 측 측정이다. 모든 설정은 dev에서만 골랐고 test 결과로 바꾸지 않았다.

  • 지식형 객관식은 세 모델 모두 무작위 수준 근처다(KMMLU·HAE-RAE·Belebele·Global-MMLU·KMMLU-Pro·KoBALT). JANSORI KMMLU 20.4(무작위 25보다 낮음)는 정답 분포와 무관한 글자 편향(A 50%·B 41%)으로 설명된다. 신호가 있는 곳은 KoBEST(JANSORI 58.7), 영어 HellaSwag·ARC(JANSORI 52.6/38.0), 한국어 bits-per-byte(JANSORI 0.752, frankenstallm 0.795, EVAFRILL 0.82; 공개 최상위 kanana-2-30b-a3b-base 0.662)다.
  • 지시 모델 2종(frankenstallm, EVAFRILL)의 생성 능력은 공개 3B급과 격차가 크다. IFEval-Ko 18.1/14.6%(공개 dense 35~71%), KorMedMCQA 14.7/9.6%(형식 실패가 많음), HRM8K는 거의 0(\boxed 형식 실패 99%), 코드 0%, judge KoMT 1.1/1.1점(공개 2.4~8.0점), ko-arena-hard 승률 0.16/0.11(기준 llama-3.2-3b-instruct = 0.5).
  • 반복 오동작은 설정으로 크게 줄었지만 품질은 오르지 않았다. dev 루프율 frankenstallm 9.1→1.2%(rp11), EVAFRILL 31.6→2.2%(card). test에서는 품질이 그대로이거나 떨어졌다(frankenstallm ko_truthful −6.6%p, EVAFRILL KoBBQ −24.3%p). EVAFRILL과 llama-3.2-3b-instruct는 제약을 모두 만족하는 설정이 없었다('설정으로 다 못 막음').
  • 다턴 시나리오(10범주 300개)에서 사용자 모델은 시나리오 통과 0%(턴 통과 0.10/0.09). 공개 3B급은 턴 0.53~0.84, 시나리오 0.30~0.63. frankenstallm은 이전 답을 그대로 복사하는 비율이 16~22%다.
  • 속도는 강점이다. JANSORI·frankenstallm은 표준 Llama 구조라 vLLM BF16에서 동시 1 371 tok/s, 동시 64 16.2~16.5k tok/s로 dense 3B급 상위다. EVAFRILL 증분 엔진은 279 / 4.2k tok/s. MoE A3B급은 동시 64에서 3.5~3.7k tok/s(가중치 57 GiB를 매 단계 읽음).
  • 34모델을 같은 조건(템플릿 없는 같은 원문 프롬프트)에 세운 통일 비교에서 사용자 모델 4항목은 31~34위다(종합 0.15~0.18, 공개 최하위 llama-3.2-3b 0.25, 1위 qwen3.6-35b-a3b 0.58). 영역별로 언어 모델링만 상위권(JANSORI 0.88, base 15종 중 4위)이고, 수학·코드는 0에 가깝다. JANSORI는 통일 조건의 KoSimpleQA 정답률 17.4%로 base 15종 중 6위였다.
  • GGUF 양자화 손실은 작다. Q8_0은 f16 대비 차이가 CI 안(0에 가까움), Q4_K_M은 한국어 bpb +0.005(JANSORI)·+0.006(frankenstallm), KoBEST −0.9%p·−0.4%p.

위 문장의 공개 모델 범위 수치(예: IFEval-Ko 35~71%)는 1순위 공개 3B급 기준이다. 2순위 7종(Qwen3.5·3.6, Gemma 4, Phi-4-mini, Nemotron 3.5, ERNIE 4.5)과 2순위 base는 모든 표·그림에 들어 있다.

사용자 모델 3종 한눈에

이 절이 보고서 전체의 기준표다. 사용자 모델은 네 항목으로 나눠 모든 표·그림에 같은 이름과 색으로 나온다. base 트랙은 JANSORI·EVAFRILL-Mo pretrain(공개 base와 비교), instruct 트랙은 frankenstallm·EVAFRILL-Mo slerp(공개 instruct와 비교)이고, 속도·메모리는 dense 3B급 BF16끼리 비교한다. 측정하지 않은 칸은 빈칸 대신 '해당 없음'과 사유를 적었다. 예를 들어 JANSORI는 base(사전학습만)라 지시 수행·대화 평가 대상이 아니고, EVAFRILL은 Mamba-2 하이브리드라 GGUF로 변환할 수 없다. 아래 섹션의 표에서도 사용자 모델 행을 맨 위에 두었고, 그림에 없는 사용자 모델은 그림 아래에 사유를 적었다.

한 줄 요약. 언어 모델링과 속도는 상위권이다. 한국어 bits-per-byte는 JANSORI 0.752로 base 15종 중 4위, frankenstallm 0.795로 instruct 19종 중 5위다. 동시 64 처리량은 JANSORI 16.5k·frankenstallm 16.2k tok/s로 dense 3B급 12종 중 1·3위다. 반면 객관식 지식, 생성, judge, 코드, 다턴은 네 항목 모두 비교군 최하위권이다. 34모델 통일 비교 종합에서도 JANSORI 31위, EVAFRILL slerp 32위, frankenstallm 33위, EVAFRILL pretrain 34위다. 칸에 마우스를 올리면 비교군 중앙값과 최고값이 나온다.

통일 비교: 모든 모델을 한 라인에

모든 모델을 같은 조건의 한 라인에 세운 비교다. 원칙은 chat 템플릿 없이 같은 원문 프롬프트를 base·instruct·사용자 모델 전부에 넣는 것이다(통일 프로토콜 U, configs/standard/unified.yaml에 측정 전 등록). 객관식·PPL은 처음부터 이 방식이었고, 나머지 영역은 다음 방법으로 같은 조건을 만든다.

  • U1 로그우도 객관식: 생성으로 풀던 KorMedMCQA·KoBBQ·TruthfulQA-ko·K2 지식을 선택지 문장 로그우도로 다시 잰다(위치·글자 편향 없음).
  • U2 few-shot 이어쓰기: HRM8K(GSM8K-ko train 예시 5개), KoSimpleQA(직접 쓴 예시 5개), 코드(HumanEval+·MBPP+ base 이어쓰기 형식을 instruct에도 적용).
  • U3 문맥 내 정렬(URIAL): 고정 한국어 머리말과 대화 예시 3개를 붙여 base도 지시에 답하게 한 뒤 IFEval-Ko·KoMT·LogicKor·K2 생성·arena-hard·다턴을 잰다.

점수는 태스크마다 0~1로 정규화한다(객관식은 무작위 보정, judge는 10점 만점 환산, PPL은 최고 bpb/bpb). 영역 점수는 태스크 평균, 종합 점수는 모든 모델에 값이 있는 영역만 같은 가중치로 평균한다. 산점도의 점선 계단은 효율 경계로, 같은 크기(또는 속도) 조건에서 가장 높은 모델들을 잇는다.

결과. 9개 영역이 모든 34모델에 채워졌다. 종합 1~4위는 MoE A3B급 qwen3.6-35b-a3b 0.585, qwen3.5-35b-a3b 0.581, qwen3.5-35b-a3b-base 0.577, qwen3-30b-a3b-2507 0.571이고, dense 3~4B급 최고는 qwen3-4b-2507 0.492(8위), exaone-3.5-2.4b 0.467(10위)이다. 통일 조건에서는 base와 instruct의 차이가 작다: qwen3.5-35b-a3b-base(3위)와 kanana-2-30b-a3b-base(5위)가 같은 계열 instruct와 비슷하거나 높다. 반대로 gemma-4-e4b-it(29위)는 템플릿 없는 조건에 약해, 모델별 최선 조건 표와 순위가 크게 다르다. 사용자 모델 4항목은 31~34위(0.15~0.18)로, 공개 최하위 llama-3.2-3b(0.25)와도 차이가 크다(종합 95% CI 폭 약 ±0.01). 영역별로 보면 언어 모델링(JANSORI 0.88, frankenstallm 0.83, EVAFRILL 0.81)은 공개 모델과 같은 수준이지만, 지식·수학·코드·지시 수행·대화·다턴은 모두 0.15 이하다.

읽을 때 주의. (1) 코드는 base 이어쓰기 형식이라 형식을 따르지 못한 모델의 MBPP+가 0에 가깝다: ERNIE-4.5 instruct는 코드 대신 설명문을 쓰고, nemotron-3.5는 378개 중 230개에서 프롬프트 끝 docstring 바로 뒤에 개행 없이 def를 붙여 SyntaxError가 났다(Nemotron·Gemma 4 계열 모두 MBPP+ 3% 이하). 프롬프트 규칙은 측정 전에 정해 바꾸지 않았다. (2) 사실성·편향 영역(KoBBQ·TruthfulQA 로그우도, KoSimpleQA)은 모든 모델이 0.02~0.26으로 낮아 순위 구분력이 작다. (3) 프롬프트가 문맥 4096을 넘어 생성하지 못한 턴(prompt_too_long)은 모델별 전체 턴의 최대 0.22%(kanana-1.5-2.1b 26/12,020)이고 빈 답으로 채점했다. EVAFRILL은 다턴에서 첫 토큰부터 '# 사용자:'를 내는 역할 넘김이 dev에서 slerp 5%·pretrain 14% 있었고 오답으로 처리했다. (4) judge가 Qwen 계열이라 Qwen 모델의 대화·생성 점수에 자기 선호가 있을 수 있다.

평가 대상과 방법

비교 원칙. base끼리, instruct끼리 비교한다. base(JANSORI, EVAFRILL pretrain)는 로그우도·PPL·코드 이어쓰기로, instruct는 각 모델 공식 chat 템플릿(사용자 모델은 학습 형식 토큰 ID)으로 생성해 채점한다. 엔진은 vLLM 0.33 BF16(EVAFRILL은 자체 증분 엔진, GGUF는 llama.cpp b12084), 문맥 4096(thinking은 16384), 공개 모델은 revision을 고정했다.

설정 선택. 객관식은 dev(KoBEST·KMMLU·Global-MMLU dev)에서 문서 시작 EOS·0-shot·chat을, 생성은 dev(GSM8K-ko train 300 + KorMedMCQA dev + 다턴 dev 100)에서 디코딩 6종(greedy, 카드 권장, repetition penalty 1.1/1.2, frequency penalty 0.3 등)과 한국어 시스템 지시를 비교했다. 생성 규칙 v3: 오동작 제약(루프 ≤2%, 언어 이탈 ≤2%, 템플릿 누출 ≤0.5%, 잘림 ≤5%)을 만족하는 후보 중 품질 최고. 규칙은 측정 전에 dev_selection.yaml에 등록했다.

표의 A와 B. A = 공통 기본 설정(greedy, thinking off), B = 모델별 dev 선택 설정. B−A 차이는 같은 문항 paired bootstrap 95% CI로 보고한다.

객관식과 PPL (base·instruct 공통 로그우도, 한 라인)

모든 객관식은 선택지 로그우도로 채점한다(chat 템플릿 없음). 사용자 모델은 학습 토크나이저와 문서 앞 EOS 규칙을 쓴다. 점수는 lm-eval 기준, 괄호는 문항 bootstrap 95% CI.

JANSORI의 dev 선택(문서 시작 EOS, dev +0.69%p)은 test에서 재현되지 않았다(ko_mc_v1 −0.46%p [−1.18, +0.26]). 공개 모델 중 smollm3-3b·llama-3.2-3b-instruct의 chat 선택도 test에서 −1.7/−1.3%p였다. 0-shot은 모든 모델에서 dev가 더 나빴다.

생성 벤치 (instruct 생성·judge, base 코드 이어쓰기)

규칙 채점 태스크(HRM8K·IFEval-Ko·KorMedMCQA·KoBBQ·ko_truthful·K2 지식)는 '정답: X'·\boxed 형식을 지시하고 형식 실패를 따로 집계한다. judge 태스크(KoMT·LogicKor·K2 생성·ko-arena-hard·KoSimpleQA)는 Qwen3.6-35B-A3B(thinking off, greedy)가 채점한다. 코드(HumanEval+·MBPP+)는 rlimit·감사 훅으로 격리 실행한다. 모든 표에 루프율·중복 3-gram·잘림을 함께 둔다.

읽을 때 주의. Qwen 계열(qwen2.5·qwen3)은 judge와 같은 계열이라 자기 선호 편향이 있을 수 있다(†). qwen3 계열은 HRM8K에서 최대 길이 2048에 걸린 비율이 34~37%라 실제보다 낮게 나온다. frankenstallm 코드는 채점 정책(unk_drop: 개행 토큰 삭제)상 0이 되는 구조다 — 개행을 복원한 unk_nl 값도 HumanEval+ 0%, MBPP+ 1.9%(A)로 낮다. base 코드 이어쓰기에서 nemotron-3-nano-base(MBPP+ 91.5%)·kanana-1.5-base(78.3%)는 첫 토큰에 바로 EOS를 내 빈 답이 대부분이다(프롬프트 끝 공백 제거 규칙은 측정 전 결정이라 바꾸지 않음).

모델별 운용 설정과 오동작

모델별로 '실사용에서 깨지지 않는' 설정을 찾았다. 오동작 = 루프(끝 600자 안 20자 이상 조각 3회 연속), 언어 이탈(한국어 질문에 다른 언어로 답), 템플릿 누출, 빈 답, 최대 길이 잘림. 품질 = dev 세 태스크 평균.

EVAFRILL(slerp 체크포인트, card 설정)은 루프 31.6→2.2%, 잘림 32.1→4.5%로 줄었지만 잘림 제약을 못 맞췄고, 품질은 7.0→4.0으로 떨어졌다. llama-3.2-3b-instruct는 언어 이탈(일본어·중국어·태국어 혼입) 3.1%가 남았다. kanana-2-30b-a3b는 fp03 단독에서 언어 이탈 10.5%('정답: E' 뒤 영어 해설)가 +sys로 0%가 됐다.

다턴 시나리오

자체 작성 다턴 벤치(custom): 10범주(수학 조건 변경·일정 기억·지시 유지·형식 변환·순서 추론·목록 추적·이어쓰기·한국어 문체·코드 수정·모름 인정) 절차 생성 300개, 3~5턴, 규칙 채점. self는 앞 턴 이력이 모델 자신의 답(오류 누적), oracle은 참조 답이다. 검사기는 참조 답 400/400 통과, 빈 답 전부 실패, 첫 턴 답 복사로는 시나리오 통과 0으로 검증했다.

GGUF 양자화 손실

BF16(vLLM)과 GGUF(llama.cpp, libllama 직접 로그우도)를 같은 토큰 ID로 비교한다. Δf16(Q8_0·Q4_K_M − f16 GGUF)이 양자화 손실, f16의 ΔBF16이 엔진·정밀도(bf16→f16) 차이다. frankenstallm은 학습 토크나이저로 다시 만든 GGUF(가중치 바이트 동일)를 썼다.

Q4_K_M에서 KMMLU가 오히려 +2.3%p(JANSORI)·+1.0%p(frankenstallm) 오르는 것은 무작위 수준 과제에서 선택지 글자 편향이 바뀐 결과로 보이며, 능력 향상으로 해석하지 않는다.

속도와 메모리 (모든 모델 한 축)

서버(vLLM OpenAI 서버 / llama-server)를 띄우고 클라이언트에서 잰다. 예열은 집계에서 뺐고 기동 시간은 따로 기록했다. W1 = ko-arena-hard 질문 128개, 출력 256 토큰 고정, 동시 1/4/16/32/64. W2 = 공유 prefix 약 2,000토큰 + 질문 64개, 동시 16, prefix caching 끔/켬. llama.cpp는 호스트 RAM 프롬프트 캐시를 끄고(vLLM과 같은 조건) prefix 켬·끔을 요청별 cache_prompt로 바꾼다.

관찰(원인 미확인): frankenstallm GGUF는 동시 4~32에서 TPOT가 JANSORI GGUF의 2~2.6배다(동시 1·64는 같음, vLLM BF16에서는 차이 없음). EVAFRILL은 배치 불변 모드(평가 재현용) 값이며, 속도만 원하면 크기 맞춤 모드가 더 빠르다.

강점과 약점

  • JANSORI: 한국어 bpb 0.752로 3B급 base 중 kanana 계열 다음, KoBEST 58.7·영어 HellaSwag 52.6으로 사용자 모델 중 가장 좋다. 표준 Llama 구조라 vLLM·GGUF 어디서나 빠르다(동시 64 16.5k tok/s). 약점: 지식형 객관식은 무작위 수준이고, base 코드 이어쓰기 HumanEval+ 0.6%·MBPP+ 1.1%.
  • frankenstallm: 속도·메모리는 JANSORI와 같은 상위권, GGUF Q8_0 손실 사실상 0. 약점: 지시 수행·형식 준수·다턴 유지가 거의 되지 않고(IFEval-Ko 18%, 다턴 시나리오 0%), greedy에서 반복이 잦다(설정으로 루프는 줄지만 품질은 그대로).
  • EVAFRILL-Mo: Mamba-2 하이브리드를 증분 엔진으로 실용 속도(동시 64 4.2k tok/s)까지 끌어올렸다. 약점: 생성 품질이 세 모델 중 가장 낮고, 반복 루프가 설정으로도 완전히 막히지 않으며(잘림 제약 미충족), 체크포인트 간 차이가 작다(객관식 33.5~33.9).
  • 비교 기준: 같은 3B급 공개 instruct(kanana-2-3b, qwen3-4b)는 IFEval-Ko 70%, 다턴 턴 통과 0.8 안팎이다. 격차의 대부분은 사후학습(지시 데이터·형식 준수) 쪽으로 보인다.

오염 가능성, 실패·미확인 항목

오염 가능성. 공개 벤치(KMMLU, HellaSwag, ARC, GSM8K 번역본, HumanEval/MBPP 등)는 공개 모델 학습 데이터에 들어갔을 수 있다. 자체 다턴 시나리오는 절차 생성이라 오염 위험이 낮다. judge는 Qwen 계열이라 Qwen 모델 점수에 자기 선호가 있을 수 있고, 2순위의 qwen3.6-35b-a3b는 judge 자신이다.

평가 중 찾아 고친 결함(모두 실패 기록 보존, 재채점·재실행):

  1. EVAFRILL 생성 체크포인트 선택이 unk 정책 차이를 체크포인트 이득으로 계산 → 같은 정책끼리 비교, slerp 재선택.
  2. IFEval-Ko 목록 인자가 numpy 배열이라 채점기 오류 → list 변환 후 재채점.
  3. korean_sp 디코딩이 개행 뒤 줄머리 공백 1개를 잃음 → 전체 디코딩으로 수정(dev 42개 조합 점수 불변, frankenstallm test 재생성).
  4. base 코드 출력에 정지 문자열 조각이 남아 SyntaxError → 재채점(예: qwen3-30b-a3b-base MBPP+ 20.1→66.7%).
  5. judge 기본 변형 목록이 이전 규칙이라 선택 설정 누락 → 'chosen' 추가 후 1순위 B judge 21,015건 실행.
  6. 성능: llama-server keep-alive 끊김, cache_prompt 고정, 호스트 RAM 캐시, kanana-1.5 head_dim 검사·spawn 진입점 → 수정 후 재측정.
  7. instruct 코드 추출이 ```markdown 안의 ```python 블록을 놓침 → 재채점(llama-3.2-3b-instruct HumanEval+ 8.0→52.1%).
  8. thinking 파싱: 템플릿이 <think>를 미리 넣지 않는 모델(SmolLM3·Gemma 4)이 생각 없이 바로 답하면 빈 답으로 저장 → 수정, SmolLM3 1,496턴 복원·judge 재판정(다턴 시나리오 0.02→0.16). Gemma 4 생각 표시(special 토큰)를 디코더가 지우던 문제도 실행 전 수정.
  9. korean_sp(frankenstallm·EVAFRILL) 출력은 개행이 <unk>라 '\n' 정지 문자열이 맞지 않음 → 수정. EVAFRILL pretrain base 코드 재채점 결과 pass 0.0 불변(잘림 1.0은 정지 실패로 부풀려진 값).

남은 미확인·한계. frankenstallm GGUF 중간 동시성 TPOT 원인; qwen3 HRM8K 잘림(34~37%); base 코드 빈 답(첫 토큰 EOS); kanana-2-3b의 think 템플릿은 thinking으로 동작하지 않아 제외; qwen3.5-4b thinking(think 행)은 greedy로 실행됐다: 저장소에 generation_config.json이 없어 등록 규칙의 대체값(greedy)이 적용됐고, 생각이 문맥 16384까지 이어져 KoSimpleQA 919/1000, IFEval-Ko 209/342가 빈 답이다. 사용자 결정으로 README 권장 샘플링 재실행(thinkrd 행)을 추가했다. 이 값은 test 결과로 고른 것이 아니라 모델 README 값 그대로다. qwen3.6-35b-a3b thinking HRM8K 형식 실패 33%도 생각 잘림(2,645/8,011)이 원인이다. 통일 비교(U)의 주의점(코드 이어쓰기 형식 불일치, 문맥 초과 ≤0.22%, EVAFRILL 역할 넘김)은 해당 절에 적었다.

재현 명령과 남은 과제

cd ko-llm-bench-suite && source ../env/paths.sh && export LT_SRC
# 객관식·PPL
$LT_VENV/bin/python -m kobench.standard.run --models <m> --suite ko_mc_v1 [--variant chat=1]
$LT_VENV/bin/python -m kobench.standard.report --suite ko_mc_v1 --ref jansori-bf16 [--table B|Q]
# 생성·채점·judge
$LT_VENV/bin/python -m kobench.standard.gen run   --models <m> --suite gen_v1 --variant A|<선택>|think
$LT_VENV/bin/python -m kobench.standard.gen score --models <m> --suite gen_v1 --variant A
$LT_VENV/bin/python -m kobench.standard.judge run; $LT_VENV/bin/python -m kobench.standard.judge score
# 운용 설정 탐색(dev)·표
$LT_VENV/bin/python -m kobench.standard.gen_report tune --models <m> --stage 1|2
$LT_VENV/bin/python -m kobench.standard.gen_report table --table A|B|think|thinkrd|tune|U
# 성능
$LT_VENV/bin/python -m kobench.standard.perf --models <m> [--engine llamacpp|evafrill]
# 보고서
$LT_VENV/bin/python -m kobench.standard.final_data --regen && $LT_VENV/bin/python -m kobench.standard.final_report

설정: configs/standard/{models,suites,gen,dev_selection,best_settings}.yaml. 데이터셋·모델 revision은 모두 고정되어 있다. 문항별 출력은 저장소에 커밋하지 않는다(데이터셋 원문 포함).

2순위 실행 범위(전부 완료). instruct 7종(qwen3.5-4b, gemma-4-e4b-it, phi-4-mini, qwen3.5-35b-a3b, qwen3.6-35b-a3b, nemotron-3.5-lightning-30b-a3b, ernie-4.5-21b-a3b): 운용 설정 탐색·생성·judge·다턴·성능·객관식 A/B. base 4종: 객관식·PPL·코드·성능. thinking 5종: think 생성·judge·다턴(+qwen3.5-4b thinkrd). 통일 비교: 1·2순위와 사용자 모델 34개 전부. 범위 밖: 공개 모델 GGUF(사용자 결정으로 제외, GGUF는 사용자 모델만), 공개 모델 문항별 출력의 저장소 공개(데이터셋 원문 포함).
